# Безопасность

## Что считается секретом

- приватный SSH-ключ и passphrase;
- URL подписки (токен доступа в пути);
- `proxy_string` (VLESS/Trojan/Hysteria2/Shadowsocks и т.п.);
- `private_key`, `pre_shared_key`, `auth_key`, `password`, `yacd_secret_key`;
- полный дамп `/etc/config/forkop` или `/etc/config/podkop`.

Инструменты маскируют эти значения по умолчанию. Исключения — явные
`reveal_secrets=true` и `podkop_config_export(mode="raw")`.

## Модель угроз

MCP-сервер работает на машине администратора и имеет SSH-доступ с правами root.
Компрометация MCP-клиента или prompt injection через логи не должны давать
произвольный shell на роутере:

- запись — только в UCI-пакет `forkop`/`podkop`, путь валидируется регуляркой;
- произвольный CLI запрещён allowlist'ом; изменяющие команды — только через
  инструменты с dry-run, бэкапом и откатом;
- чтение файлов — только из `/etc`, `/var`, `/tmp`, `/proc`, `/sys`, `/rom`,
  `/usr/share`, без `..`;
- read-only режим `PODKOP_MCP_READ_ONLY=1` блокирует все изменения.

Остаточный риск: SSH-ключ с правами root. По возможности используйте отдельный
ключ и ограничения в `authorized_keys` (`from=`, `command=`), а также
`PODKOP_MCP_READ_ONLY=1` для сессий, где нужен только мониторинг.

## Host key policy

По умолчанию `reject`: неизвестный ключ хоста не принимается. Для первого
подключения добавьте ключ в `known_hosts` вручную или явно задайте
`PODKOP_MCP_HOST_KEY_POLICY=accept-new` (ключ добавится, но несовпадение
известного ключа останется ошибкой).

Политика `ignore` есть только для изолированных лабораторных стендов; в README
она не рекомендуется.

## Бэкапы и откат

Перед каждой записью создаётся копия `/etc/config/<pkg>` в
`/etc/podkop-mcp/backups/<UTC>-<reason>.uci` с sha256. Если reload завершился
ошибкой или сервис не поднялся за отведённое время, бэкап восстанавливается
автоматически, выполняется `uci commit` и повторный reload.

Бэкапы — обычные UCI-файлы; их можно просмотреть через
`podkop_backup_list` и восстановить через `podkop_backup_restore`.

## Секреты в логах

Логи (`podkop_logs`) проходят через redaction: URL подписок, proxy-ссылки и
токены маскируются. Тем не менее не публикуйте полные логи в issue без проверки.

## Сообщение об уязвимости

Не создавайте публичный issue с секретами. Используйте GitHub Security Advisory
или приватный контакт владельца репозитория; приложите минимальный сценарий без
реальных ключей и URL.
