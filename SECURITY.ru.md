# Security policy

## Что считается секретом

- приватный SSH-ключ и его passphrase;
- URL подписок (содержат токен доступа);
- `proxy_string` (VLESS/Trojan/Hysteria2/Shadowsocks и т.п.);
- `private_key`, `pre_shared_key`, `auth_key`, `password`, `yacd_secret_key`;
- содержимое `/etc/config/forkop` и `/etc/config/podkop` целиком.

Сервер маскирует эти значения по умолчанию. `reveal_secrets=true` и
`podkop_config_export(mode="raw")` — осознанное исключение.

## Модель угроз

MCP-сервер запускается на машине администратора и имеет SSH-доступ к роутеру.
Компрометация MCP-клиента (или prompt injection через содержимое логов) не должна
давать произвольный shell на роутере:

- запись — только в UCI-пакет `forkop`/`podkop`, путь валидируется;
- произвольный CLI запрещён allowlist'ом, изменяющие команды — только через
  инструменты с dry-run/бэкапом/откатом;
- чтение файлов — только из `/etc`, `/var`, `/tmp`, `/proc`, `/sys`, `/rom`,
  `/usr/share`, без `..`;
- read-only режим `PODKOP_MCP_READ_ONLY=1` блокирует все изменения.

Остаточный риск: SSH-ключ с правами root. Используйте отдельный ключ и
ограничение `from=`/`command=` в `authorized_keys`, если это возможно.

## Host key policy

По умолчанию `reject`: неизвестный ключ хоста не принимается. Для первого
подключения к новому роутеру добавьте ключ в `known_hosts` вручную или явно
установите `PODKOP_MCP_HOST_KEY_POLICY=accept-new` (ключ будет добавлен, но
несовпадение известного ключа всё равно останется ошибкой).

## Как сообщить об уязвимости

Не создавайте публичный issue с секретами. Напишите владельцу репозитория
приватно (GitHub Security Advisory) и приложите минимальный сценарий
воспроизведения без реальных ключей и URL подписок.
